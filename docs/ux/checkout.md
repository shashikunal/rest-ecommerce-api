# Checkout + Payment + Confirmation + Returns/Refunds + Reviews

Checkout steps (progress indicator, back-preserves-state): 1 Cart-review → 2 Address (select/add, default) → 3 Delivery option → 4 Review (items/totals/coupon/address) → 5 Payment → 6 Confirmation. Pricing summary sticky; coupon inline-validate (generic failure reasons); final review checkbox; Pay button disabled until valid.
Failure UX (cart preserved always; messages user-safe, no raw errors): INSUFFICIENT_STOCK → line-level flags + "Adjust cart" · PRICE_CHANGED → old→new + re-confirm · COUPON_INVALID → inline reason + remove · ADDRESS_INVALID → field errors · PAYMENT_FAILED → retry with same idempotency context (new attempt, no double-charge; show attempt history) · PAYMENT_PENDING → "We're confirming with your bank" + poll + notify on resolve (never claim success early) · TIMEOUT → "Couldn't confirm — check Orders before retrying" (prevents dup) · SESSION_EXPIRED → login modal preserving draft · 429 → "Too many attempts, retry in N min" with Retry-After countdown · 5xx → full-step error + retry.
Confirmation: orderNo + status timeline + payment state + address/ETA + tracking entry + support link; "confirmation email on its way" (async note). Order states → UI: PENDING_* (amber, Cancel allowed) · PAID/PROCESSING (blue) · SHIPPED (tracking link) · DELIVERED (Return CTA ≤30d) · CANCELLED/FAILED (grey/red, reason + reorder CTA) · RETURN_REQUESTED→RETURNED→REFUNDED (purple chain + refund card). Timeline + badge + allowed/unavailable actions per state; polling only for pending states.
Returns: Order → select items/qty → reason (+photo optional ≤5MB) → review → submit → RMA status tracker (REQUESTED→APPROVED→PICKED→INSPECTED→REFUNDING→REFUNDED/REJECTED with reason shown). Refund card: amount, method-last4 only, ETA note, states pending/processing/completed/failed(+retry-contact). Reviews: stars + text (+photo optional) + verified-purchase badge; moderation states (pending → visible after approval; rejected shows reason to author only); dup → edit-existing prompt; guest → login nudge.
