# Admin UX (role-gated; staff/support subsets per authorization.md)

Dashboard: KPI cards (orders today, revenue, pending-payments, low-stock count, open returns, failed webhooks/DLQ) + queues (awaiting fulfilment, RMA triage, review moderation) + system banner (consumer lag/outbox backlog — ops only). Real-time labeled (order/payment states) vs eventual (analytics aggregates, "updated hourly").
Products: table (search/filter status/category, cursor pages; mobile → cards) → editor (title/slug auto/desc/brand/category/attrs/media-uploader/variants-table with SKU uniqueness inline check/publish-state buttons) + unsaved-changes guard + 409 version-conflict resolver (theirs/yours/merge-manual) + 403 permission wall.
Inventory: SKU table (available/reserved/sold + low-stock flags) + Adjust modal (delta ±, reason required, no direct set) + adjustment history + audit link; insufficient-permission → read-only with request-access note.
Orders: search (orderNo/email) + status filters + detail (customer, items snapshot, payment attempts, shipments, timeline, audit trail) + action buttons strictly per machine (Confirm/Ship/Deliver/Cancel; illegal transitions absent, never free-form status edit). Returns/Refunds: triage queue → RMA detail (items/reason/photos) → Approve/Reject → Receive/Inspect → Refund (amount prefilled ≤ remaining, idem-safe double-submit lock) with customer/staff/admin views separated. Reviews: moderation queue (flag reason, approve/reject + audit). Audit logs: filters (actor/action/resource/date/corrId) + redacted secrets. All destructive acts → confirm modal + success toast + audit entry.
