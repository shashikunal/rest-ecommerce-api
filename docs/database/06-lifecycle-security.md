# 06 Lifecycle + Security + Atlas + Backup/DR

Soft-delete (deletedAt + status): products/categories/brands/coupons/promotions/addresses/users. Hard-delete: nothing business-critical; sessions/reservations via TTL; carts TTL 30d abandoned; notifications TTL 90d; outbox SENT>7d delete; inbox PROCESSED>30d delete; idem money 90d TTL; webhooks 1y; audit 2y then archive to cold store; orders/payments/refunds/returns/reviews never TTL (7y retain).
Classification: public (published catalog); internal (prefs, carts); sensitive (PII, addresses, order totals); highly sensitive (passwordHash, tokenHash, OTP hashes, payment refs) — hashes only, AES-at-rest via Atlas, TLS in transit, field exclusion in repos/mappers, audit on access.
Atlas: separate projects DBs (dev/staging/prod); least-privilege DB users per env (app user: readWrite, no admin); IP allowlist / private endpoint prod; credentials in secret manager, never git; encryption at rest + in transit; profiler/slow-query alerts.
DR: continuous backup + PITR; RPO≤5m RTO≤30m (assumptions); restore drill quarterly to staging; Redis rebuild from Atlas; Kafka 7d replay re-drives derived state; object store versioned. Scenarios: primary failover (retry writes, read-your-write may lag → surface "processing"), region loss (restore PITR to new region + replay Kafka), bad deploy (Vercel rollback + no destructive migration without backfill plan).
