# 09 Interview Review + Anti-Patterns

Q&A (this design): Mongo over PG — document catalog + snapshots + tx where needed + Vercel pooling; PG wins only for join-heavy ledger (absent). Embed vs ref — embed owned/history-bounded (order items, cart lines), ref independent/hot (variants, inventory, user→orders). Oversell — single-doc cond-dec + version inside checkout tx + TTL reservations. Tx here — T1–T5 only; avoided for reads/single-writes (atomic ops cheaper). Index/write trade — every index query-justified; hot docs keep ≤3 indexes. Pagination — cursor `{sort,_id}` (stable, no skip-cost); offset only tiny admin lists. Failover — transient retry then 503; version-guards prevent half-writes. 1000x — shard inv-by-sku/orders-by-user, OpenSearch, CQRS, archive audit. History correctness — immutable snapshots, never live product joins. Dup payments — idem unique + providerEventId + server-fetch + version. Outbox/inbox — tx+claim+at-least-once+dedupe. Evolution — additive fields + dual-read renames. Big collections — capped arrays, TTL ephemeral, archive audit. Hot docs — isolate (inventory split from variant), spread (reservations per order). Monitor — slow-query, pool, tx-conflicts, dup-key rate, outbox lag, TTL deletes.
Avoided: unbounded arrays (caps everywhere); $lookup sprawl (snapshots instead); tx-everywhere; missing/over-indexing; skip() deep pages; GridFS blobs; plaintext secrets; Redis-as-truth; Kafka-as-DB; giant product/user/audit docs; uncontrolled schema mutation (additive + review).
