# Ops: Schema Evolution + Registry + Security + Retention + Observability + Local/Vercel + Boundaries + Trade-offs

Evolution: additive-only (new optional fields; consumers ignore unknowns); rename → dual-field window; breaking → `eventType.vN+1` dual-publish + consumer dual-read, then deprecate. Never silent resemantic.
Registry: deferred — JSON + in-repo contract tests + CI envelope validator suffice at this scale; migrate to Schema Registry (Avro/Protobuf) when >3 teams or >100 msg/s. Reason documented; path: add registry check in EventPublisher, keep envelope.
Security: SASL/SCRAM + ACLs (producer-write-only per topic, consumer-read-only per group); TLS in transit; secrets in manager; payloads exclude passwords/OTPs/tokens/cards, minimal PII. Retention: business 7d, notify/search 3d, DLQ 30d, retry 7d (why: replay window vs storage cost; audit permanence lives in Atlas, not Kafka).
Metrics: publish ok/fail + latency, lag per group, throughput, retries, DLQ count, processing latency, event age, dups-skipped, skew; all logs carry eventId/corrId/aggregateId; alerts: lag, DLQ, producer-fail, retry-storm, outbox-backlog (warn/critical per reliability).
Local: Docker Kafka + auto-create topics per catalog + seed sample events (script in Phase 28, not here). Vercel: API only writes outbox + (publisher is external worker); consumers/workers deploy separately (Railway/Render/Fly) — never in request handlers, never in-memory queues.
Boundaries: module → produced/consumed map = catalog file; Kafka never bypasses domain rules (order transitions still version-guarded on consume). Trade-offs: Kafka vs HTTP (durability+fan-out vs latency — sync kept where user waits); per-domain topics vs per-event (bounded sprawl + key-order); JSON vs Avro (velocity now, registry later); at-least-once+inbox vs exactly-once (former is honest + sufficient); outbox vs direct (safety); retry-topics vs delay-queues (durable, observable). Anti-patterns forbidden: Kafka-for-every-call, Kafka-as-DB, missing eventId/version/key, no idempotency, infinite retry, silent schema change, >64KB payloads, secrets in events, SDKs in domain, Vercel consumers, Kafka masking bad boundaries.
