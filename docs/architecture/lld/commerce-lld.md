# Commerce LLD (product→notify; entities, rules, tx, failures)

- Product/catalog: Product{slug unique, status draft/published/archived, attrs, mediaURLs[]} Variant{sku unique, attrs, priceRef}; publish requires ≥1 variant + inv row; soft-delete (status) ; admin-only writes + audit.
- Pricing: quote = base→variant→promo→coupon(caps, no-stack default)→tax→shipping; minor-unit ints, half-up; snapshot {items[], subtotal, discounts, tax, shipping, total, couponCode} into order (immutable).
- Cart: lines {skuId, qty, priceCached, validatedAt}; add/update/remove/clear/merge(login: guest→user, sum-qty cap); on read: drop deleted SKUs, refresh price (flag changed), check inv (flag short), expire coupon (flag); version per cart for write-races.
- Inventory: {skuId, available, reserved, sold, version}; reserve: cond `available>=qty` `$inc{-available,+reserved}` in checkout tx; release: reverse; commit(paid): `reserved→sold`; TTL 15m + sweeper; guards block negative/double-release (idempotent releaseKey).
- Checkout (sync): user→address→lines→price→coupon(atomic usage)→reserve→payment-intent→order(PENDING_PAYMENT)+outbox [ONE tx: reserve+order+outbox] → respond 201; async: events→notify/analytics. Compensate: pay-fail → FAILED + release; order-fail → tx rollback (no reserve held); event-fail → sweeper.
- Order: {items snapshot, price/address/customer snapshots, payId, invRefs, status, version}; machine CREATED→PENDING_PAYMENT→PAID→PROCESSING→SHIPPED→DELIVERED (+CANCELLED/FAILED/RETURN_REQUESTED→RETURNED→REFUNDED); guarded `transition(expectedVersion)`; invalid →409; side-effects per transition (reserve/pay/ship/notify/refund).
- Payment: Provider iface {create,authorize,capture,cancel,refund,verifyWebhook}; attempt ledger {orderId, amount, status, providerRef, idemKey}; webhook: HMAC+5m window+idem → server-fetch verify → tx confirm (payment+order PAID+outbox); stale/out-of-order ignored by version; reconcile cron settles unknowns.
- Refund/return: RMA{id, orderId, items, reason, state REQUESTED→APPROVED→PICKED→INSPECTED→REFUNDING→REFUNDED/REJECTED}; eligibility (≤30d, delivered, not-consumed); refund idem per RMA; partial supported; dup blocked by unique(rmaId)+state guard.
- Shipping: Carrier iface {quote,create,getTracking,webhook}; shipment{orderId, label, tracking, status}; status events drive order SHIPPED/DELIVERED idempotently.
- Coupon/promo: {code unique, window, globalCap, perUserCap, minOrder, scope SKUs/cats, stackRule}; redeem = atomic global `$inc` + per-user unique + limit checks in checkout tx (short Redis lock only if proven hot).
- Reviews: {productId, userId unique-pair, orderId verified, rating 1–5, text, status pending/approved/rejected}; only delivered-order owners; moderation queue; abuse: 1/product/user + 429 + profanity-flag.
- Notify: NotifyService{send(templateId, to, vars, idemKey)} + EmailAdapter(Nodemailer)/future SMS; prefs checked first; retries exp+jitter 3–5 →DLQ; delivery status persisted; never blocks request path.
