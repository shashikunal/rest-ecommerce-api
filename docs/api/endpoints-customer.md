# Customer Endpoints (request/response/validation/auth/errors/limits)

Auth: see authentication.md. Users: `GET /users/me` / `PATCH /users/me` (allowlist firstName/lastName/phone) customer-self.
Catalog (public GET; admin write in admin file): `GET /products?category=&brand=&minPrice=&maxPrice=&search=&sort=&limit=&cursor=` → 200 `{data:[ProductDTO],pagination}` (60/m); `GET /products/{slug}` → ProductDTO `{id,slug,title,description,brand{},category{},variants[{sku,attrs,price,availability}],media[],createdAt,updatedAt}` — no `_id/__v/cost/internal` fields; `GET /categories|/brands|/products/{id}/reviews`.
Cart (customer, 60/m): `GET /cart` → `{lines[{itemId,sku,qty,unitPrice,lineTotal,staleFlags}],totals{…recalculated},version}`; `POST /cart/items {sku,qty 1..50}` → 201 (409 OUT_OF_STOCK / 422 SKU_UNAVAILABLE); `PATCH /cart/items/{itemId} {qty}` (version-checked →409 CART_STALE); `DELETE …/items/{itemId}` 204; `DELETE /cart` 204. Wishlist: GET/POST/DELETE (dup →200 existing, no 409). Addresses (owner): GET/POST/PATCH/DELETE + `POST /addresses/{id}/set-default`; ownership 404-safe.
Checkout (customer, 10/m, Idempotency-Key required): `POST /checkout/preview {addressId,couponCode?}` → 200 totals (no side-effects); `POST /checkout/validate` → 200 {ok,issues[]} / 422; `POST /checkout {addressId,paymentMethod,couponCode?}` → 201 `{orderId,orderNo,status:PENDING_PAYMENT,payment{…}}` (409 INSUFFICIENT_STOCK / 422 COUPON_INVALID / 409 IDEMPOTENCY_CONFLICT). Never returns orchestration internals.
Orders (owner, cursor): `GET /orders?limit&cursor` · `GET /orders/{id}` (full snapshots) · `POST /orders/{id}/cancel` (CREATED/PENDING only →200 CANCELLED else 422 ORDER_NOT_CANCELLABLE).
Payments (owner, 5/m, idem): `POST /payments {orderId,method}` → 201 `{paymentId,status}`; `GET /payments/{id}` (poll; 504-gateway → status PENDING, retry poll); `POST /payments/{id}/cancel` (pre-capture only).
Returns (owner): `POST /orders/{id}/returns {items,reason}` → 201 RMA (422 RETURN_NOT_ELIGIBLE); `GET /returns|/returns/{id}` (RMA state; refund amounts visible, provider internals hidden).
Coupons: `POST /coupons/validate {code,orderDraft}` → 200 {valid,discount,reason?} (reasons generic enough to avoid rule-mining: EXPIRED/INVALID/MIN_NOT_MET). Reviews: `GET /products/{id}/reviews` public cursor; POST (verified-purchase else 422) · PATCH/DELETE owner (60/m + abuse 429). Notifications (owner): GET cursor · `PATCH /notifications/{id}/read` · `POST /notifications/read-all` (204) · GET/PATCH `/notification-preferences`. Media: `POST /media/upload-url {contentType,size,ownerType}` (admin/seller, 10/h) → 201 `{uploadUrl,objectKey,expiresIn}`; MIME allowlist (jpeg/png/webp), ≤5MB, 400 on violation; client PUTs direct to S3 (no file bytes through API).
