# API Standards + Versioning + Resource Map (Phase 6 — contract only)

REST + JSON, base `/api/v1`, kebab-case plurals (`/product-variants` avoided — nest `/products/{id}/variants`). URL versioning (cacheable, explicit, gateway-friendly); additive changes never bump; breaking → `/api/v2` + 6-month sunset (`Sunset` + `Deprecation` headers + changelog). No v2 in scope.
Methods: GET (safe, retryable), POST (create/action; idem where money), PUT (full replace, admin config), PATCH (partial, allowlisted fields only), DELETE (remove/revoke; money uses action POST, never DELETE). State changes via action endpoints (`POST /orders/{id}/cancel`) — never raw `PATCH {status}`.
Status: 200 read/update · 201 created · 202 async-accepted (notify-retry, bulk ops) + `operationId` + status URL · 204 no-body (revoke/read-all) · 400 malformed · 401 unauthenticated (generic) · 403 forbidden · 404 no-enumeration-safe · 409 conflict/version/idem-mismatch · 422 semantic (coupon invalid, transition illegal) · 429 + `Retry-After` · 500/502/503/504 mapped per failure matrix (never stacks/vendor errors).
Resource inventory (70+ endpoints, detail in endpoints-customer/admin): auth(10) · users/sessions(4) · catalog(12) · search(1) · cart(5) · wishlist(3) · addresses(5) · checkout(4) · orders(3) · payments(3)+webhook(1) · returns(3) · coupons(1) · reviews(4) · notifications(4) · media(1) · admin(~25: users/products/cats/brands/variants/inv/orders/payments/refunds/returns/coupons/promos/reviews/notify/audit/analytics).
