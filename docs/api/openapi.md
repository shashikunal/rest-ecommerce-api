# OpenAPI Structure + Reusable Components + Security Schemes + Implementation Plan

OpenAPI 3.1 layout (design artifact; implemented in backend foundation phase): `docs/openapi/openapi.yaml` (info/servers/tags) + `paths/*.yaml` per domain + `schemas/*.yaml` + `parameters.yaml` + `responses.yaml`. Tags: Auth, Users, Catalog, Search, Cart, Wishlist, Addresses, Checkout, Orders, Payments, Webhooks, Returns, Coupons, Reviews, Notifications, Media, Admin. Servers: prod + staging (no localhost in committed spec).
Component schemas (request/response DTOs, never Mongo docs): User, Session, Product, Variant, Category, Brand, MediaRef, Cart, CartItem, Address, PriceTotals, Order, OrderItem, Payment, Refund, Return(RMA), Coupon, Promotion, Review, Notification, NotificationPrefs, Pagination, Error, ValidationError. Shared parameters: `CursorParam, LimitParam(1..50), SortParam, SlugParam, IdParam(uuid), IdempotencyKeyHeader, CorrelationIdHeader`. Shared responses: `BadRequest(ValidationError), Unauthorized, Forbidden, NotFound, Conflict, Unprocessable, RateLimited(+Retry-After), InternalError`.
Security schemes (match architecture exactly): `bearerAuth` (JWT access, for docs `Authorize`) + `cookieAuth` (refresh cookie, noted HttpOnly — exercised via browser, not Swagger `Try it` with real tokens) + `webhookSig` (HMAC header, documented not fillable). No OAuth2/password flows documented (not implemented).
Doc quality bar: every path gets summary + business description (not "Creates X" — e.g. "Reserves inventory + creates order + payment intent atomically; async notify") + auth + idem/limit notes + request/response examples + error table. Compatibility: additive optional fields only; renames/type/required/semantic changes → new version + `Sunset`; generated contract tests (schemathesis/Dredd in CI) fail on drift; client guidance: ignore unknown fields, never send unknown required.
