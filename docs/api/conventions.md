# Conventions: Pagination + Filtering + Sorting + Idempotency + Rate Limits + Caching + Timeouts/Retry/Async

Pagination: cursor everywhere high-volume (`?limit=20&cursor=…`, default 20, max 50, opaque base64 `{sortKey,_id}`; invalid cursor →400 INVALID_CURSOR). Resp `{data:[],pagination:{limit,nextCursor,hasMore}}`. Offset (`?page&limit`) only tiny admin lists (≤200 rows). Sort: `?sort=price | -price,createdAt …` allowlisted per resource + `_id` tiebreak; invalid →400. Filters: `?category=&brand=&minPrice=&maxPrice=&status=` allowlisted, validated, AND-combined; no `$` operators, no raw expressions; too-complex →400.
Idempotency-Key (uuid v4, required: POST /checkout, POST /payments, POST /refunds(via returns), POST /orders/{id}/cancel; optional: POST cart-items): TTL 24h; same key+same hash → replay stored response (200/201 original status); same key+different body →409 IDEMPOTENCY_CONFLICT; concurrent → one executes, other waits+replays.
Rate limits (contract surface, impl in LLD): global 200/m/IP · register 10/h · login 5/15m · OTP 4/10m + 5/OTP · reset 3/15m · search 60/m · cart 60/m · checkout 10/m · pay 5/m · admin 60/m · upload 10/h · webhook 100/m. 429 body + `Retry-After` + `RateLimit-Limit/Remaining/Reset` headers.
Caching: public catalog GET `Cache-Control: public, max-age=60` + ETag (conditional 304); private (cart/orders) `private, no-store`; never cache authed money states publicly. Timeouts: client budget 30s; server DB 5s/Redis 3s/gateway 10s → 503/504 per matrix. Retry: GET safe; POST only with same Idempotency-Key; checkout/pay never blind-retried (poll `GET /orders/{id}` / `GET /payments/{id}`). Async: 202 + `{operationId,statusUrl}` for notify-retry/bulk; status endpoint returns pending→done. Eventual-consistency notes: search ≤60s lag, notifications pending-state, analytics not real-time — clients poll, never assume instant.
