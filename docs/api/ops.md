# API Ops: Security + Observability + Contract Tests + Compatibility + Performance + State Matrix + Boundaries + Interview + Diagrams

Security→endpoints: authN (all but public catalog/auth-issue) · authZ owner/admin (all `:id` + admin/*) · limits (per conventions) · Zod (all inputs; NoSQL-safe allowlists) · XSS (output-escaped; no reflected HTML) · CSRF (cookie endpoints + Origin) · CORS allowlist · Helmet headers · body 100kb (media-meta 1mb) · upload MIME/size/presigned · enumeration-safe 404/401-generic · brute-force lockout (login/OTP) · replay (webhook window + idem keys) · HMAC webhooks.
Telemetry per request: corrId, route/method/status/latency, userId-hash (never PII), error code, limit verdict; never log passwords/OTPs/tokens/secrets. Contract tests (CI): schema-valid req/resp + status codes + error shape + auth matrix + pagination + idem replay/conflict + 429 headers — OpenAPI is the asserted source.
Compat: safe = new optional fields/endpoints; breaking = remove/rename/type/required/semantic → version bump + Sunset 6mo. Perf: cursor paging, projection (no `?fields` free-form — fixed DTOs), gzip, catalog ETag, no batch endpoints v1 (unjustified), N+1 banned (repo dataloader/bulk reads).
State matrix: cancel→CREATED/PENDING only; returns→DELIVERED only; refunds→CAPTURED only; transitions invoke machine (version-checked), never client status writes. Separation: `HTTP-DTO → Command → Domain → Persistence` and back via mappers (no `_id/__v` leak); `API → Service → tx+outbox → Kafka` (API never publishes directly; workers never exposed via REST).
Interview answers (this contract): REST (cacheable CRUD + actions for machines) · `/api/v1` URL versioning (explicit, CDN-safe) · PATCH allowlisted-partial vs PUT replace · POST idem on money (key+hash+replay) · limits Redis sliding-window + 429 contract · cursor (stable, no skip cost) · enumeration via generic 401/404 + throttles · JWT-access + rotating refresh + reuse-detect · RBAC + owner checks · versions additive, Sunset for breaks · webhooks HMAC+timestamp+providerEventId, isolated from customer auth · API writes outbox, workers consume (never REST→Kafka hope) · search/notify lag documented with poll/status · Redis-down 503 money/degenerate reads · Kafka-down checkout still 201 (outbox buffers), notify pending · dup-checkout/pay blocked by key+unique+version · status immutable by clients (action endpoints only).
Diagrams (readable, in endpoints files context): lifecycle (edge→corrId→limit→authN→authZ→Zod→controller→service→domain→repo→mapper→resp) · login/refresh-reuse · OTP request/verify · checkout tx→outbox · payment+webhook verify · cancel version-check · RMA→refund · API→outbox→Kafka · error map · limit allow/deny · idem execute/replay/conflict · cursor encode/decode · admin RBAC gate.
