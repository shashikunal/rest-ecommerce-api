# Errors + Correlation (canonical contracts)

Error body (all failures): `{"error":{"code":"ORDER_NOT_CANCELLABLE","message":"…human, no internals…","details":[],"correlationId":"…"}}`. Codes: VALIDATION_ERROR(400) · UNAUTHENTICATED(401) · FORBIDDEN(403) · NOT_FOUND(404) · CONFLICT(409: version/email/sku/idem-mismatch) · UNPROCESSABLE(422: coupon invalid, illegal transition) · RATE_LIMITED(429 + `Retry-After`) · INTERNAL(500) · BAD_GATEWAY(502)/UNAVAILABLE(503)/TIMEOUT(504). Never: stacks, DB errors, service names, secrets.
Validation details: `[{field:'email',code:'INVALID_EMAIL',message:'…'}]` mapped 1:1 from Zod issues (path→field, code→upper-snake). Unknown fields stripped (not echoed).
Correlation: client may send `X-Correlation-ID` (uuid v4, else server mints); echoed on every response; propagated to logs, Mongo (comment), Redis (key suffix in debug), Kafka headers, downstream events as causationId. `requestId` internal (logs); clients use correlationId for support tickets.
Failure matrix (HTTP/code/retry/client-action): validation 400/VALIDATION_ERROR/no/fix payload · auth 401 generic/no/re-login · forbid 403/no/contact support · 404/no/verify id (owner-scoped) · conflict 409/CONFLICT/refetch-then-retry with new version · 422/no/fix business state · 429/retry-after/wait+backoff · DB-timeout 503/DEPENDENCY_UNAVAILABLE/retry-idempotent-only · Redis-down 503 on money paths · Kafka-down 202-or-503 per endpoint (checkout still 201 via outbox; notify-status 202 pending) · gateway-timeout 504/PAYMENT_PENDING/poll status, never blind re-POST (reuse Idempotency-Key) · shipper 503/SHIPPING_UNAVAILABLE/retry later.
